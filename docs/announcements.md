# Company announcements

The management announcement table shows the creator's current display name in ავტორი and omits personal read status. The employee table retains personal read status. The list query joins the existing author account and returns the name without exposing contact or authentication fields.

Creators are excluded from their own publication's delivery recipients. Their publications remain visible in the directory and are shown as read. Existing self-delivery rows are ignored by login-modal, unread-dot and notification inbox queries without deleting announcement history.

See [Announcement live updates](announcements-realtime.md) for SSE delivery, file ownership, reconnect behavior and deployment requirements.

`/announcements` is the authenticated employee announcement directory. `/manage/announcements` adds publishing through a right-side shadcn Sheet and requires `manage.access` plus `announcements.manage`. HR, admins, and the existing protected owner have publishing grants. Permissions and active account/employment state are rechecked from persistence inside each service transaction. Ordinary employees can read company announcements and acknowledge only their own reading state.

Published announcements are immutable in this first version. The publisher enters a title and plain-text body and selects a delivery mode. A request ID scoped to the publisher makes retries idempotent; altered content with the same request ID is rejected. Publication, the eligible employee snapshot, and any inbox delivery commit atomically.

- With modal display enabled, signed-in recipients see new announcements immediately through SSE. Signed-out recipients see pending announcements after signing in. The server returns the oldest eligible item and remaining count, so only one full body is transferred at a time. New arrivals join behind the open item. A queue indicator shows progress such as 1 / 3.
- With login display disabled, recipients receive a linked alert in the existing bell and notification inbox. These announcements never open automatically.
- Closing the automatic modal updates `dismissed_at` and advances the queue. That item stays suppressed for existing sign-ins, but a later sign-in can remind the employee again. Choosing წავიკითხე records `read_at` and permanently removes it from automatic delivery. Concurrent dismissal cannot undo reading. The server compares dismissal with the trusted Better Auth session creation time; the browser supplies neither identity nor sign-in time.
- Voluntary viewing remains available after dismissal or reading. Closing a delivered, unread modal announcement also defers its automatic reminder for the current sign-in, avoiding immediate reopening behind the reader. Closing ordinary or historical undelivered content changes no reading state. Explicit reading also marks that employee's corresponding bell notification seen. Marking a bell item seen does not itself claim the announcement was read.
- Publication targets currently active or invited accounts with active employee records. Suspended/inactive accounts do not receive new delivery records. Future employees can browse historical announcements voluntarily without receiving a backlog of old login popups.

The employee directory uses a TanStack Table with Georgian dates, titles and read status. Delivery details are omitted. Management retains the TanStack Table and ჩვენება column. Both views use validated URL search, read/unread filtering, stable newest/oldest sorting, 20-row server pagination and shared shadcn controls. Content is rendered through React escaping. Responses and query caches are private and scoped to the actor. Automatic delivery pauses only while a manually opened announcement reader is active, avoiding stacked announcement dialogs, then resumes.

The existing `show_on_login` column now selects modal delivery; it is retained to avoid a needless data migration. `dismissed_at` stores the latest dismissal rather than the first. No new table or migration is needed for modal queues or the announcement table.

Migration `0027_announcements.sql` adds announcement/recipient persistence and an optional announcement link on existing notifications. Existing inbox entries retain their content and read status. PostgreSQL 18 supplies UUIDv7 identities. No publication editing, deletion, rich HTML, attachments, scheduling, targeting UI, or complaints workflow is included in this version.

Verification uses Vitest/React Testing Library for publishing, acknowledgement failure/retry, manual versus automatic display, modal queue progress and arrivals, employee versus management table columns, bell links, and URL search synchronization. `RUN_ANNOUNCEMENTS_DB_TESTS=1` enables an isolated local PostgreSQL suite covering authorization, revoked grants, validation, retry concurrency, delivery mode, sign-in reminders, recipient isolation, sticky reading, historical browsing, and list behavior. It creates and removes a dedicated test database and never publishes fixtures to the application database.
