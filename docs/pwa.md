# Teamwork PWA

Teamwork supports installation as a standalone app. Authentication, attendance,
approvals, and other business actions require an internet connection.

## Included functionality

- A Georgian manifest with a stable `/` identity and launch URL. The launch route
  still asks the server for the current session and redirects accordingly.
- 192px and 512px app icons, a maskable 512px icon, an Apple touch icon, and an SVG
  favicon. The T mark stays inside the maskable icon's safe area.
- An install control beside the theme switcher on auth pages and in the app header.
  On desktop, it appears only after the browser offers a native install prompt.
  On iOS, it shows Georgian instructions for the Share menu flow. Installed windows
  hide the install control. Dismissing a desktop prompt hides the control until the
  browser offers installation again.
- A static Georgian offline document that requires neither React nor authentication.
  Retrying loads the original URL. The page contains no employee or session data.
- A connection notice in an open app and a prompt to apply a new version.

## Cache and update boundaries

`scripts/pwa.ts` configures `vite-plugin-pwa` with `injectManifest` and writes the
offline document to the client build. Only public compiled JavaScript, CSS, fonts,
icons, the manifest, and the offline document are precached. There is no runtime
response cache, persisted Query cache, offline mutation queue, or background submission.

`src/service-worker.ts` fetches document navigations from the server, preserving
redirects, authorization failures, and HTTP errors. Only a failed network request
falls back to the static offline document. Auth endpoints, server functions,
non-document requests, and non-GET requests bypass this navigation route.
Authenticated HTML and business responses never enter Cache Storage.

The first worker claims clients after installation. Later workers wait for approval.
The update action activates the new worker and reloads controlled app tabs. The
prompt asks users to save changes in every open tab. Choosing later keeps the current
version for the session. Focus, visibility, and reconnection events check for updates
at most once a minute while online and visible; there is no polling timer.

Workers remain disabled during `pnpm dev` to avoid interfering with HMR. The manifest
and worker are generated by the production build. A desktop install button does not
appear without a browser-provided install prompt. Icons, iOS instructions, and
`/offline.html` can still be inspected during development. Full installation, offline,
and update testing requires `pnpm build` followed by `pnpm preview`.

## Deployment

Run `pnpm build` and deploy the complete `.output` directory using the existing Nitro
setup. The build includes `service-worker.js`, `manifest.webmanifest`, `offline.html`,
and `icons/` in `.output/public`. Committed PNGs mean the Windows icon regeneration
script is not needed during Docker or Linux builds.

Use HTTPS in production. Localhost is supported for verification. The existing Caddy
deployment terminates HTTPS. Nitro route rules give the worker, manifest, and offline
document `Cache-Control: no-cache`; a CDN or reverse proxy must preserve these headers
and content types. The root worker controls `/`. Personalized responses retain their
existing `private, no-store` headers.

Push notifications and background synchronization are outside this implementation.

## Verification

1. Run `pnpm exec tsc --noEmit`, `pnpm test`, and `pnpm build`.
2. Run `pnpm preview` and open the app in a fresh browser session on localhost.
3. In Application tools, check the manifest, icon sizes, active worker, and Cache
   Storage. Only the public files listed above should be present.
4. Check installation in Chrome or Edge and from the Share menu on iOS. The actual
   OS installation flow requires verification on the intended devices.
5. After worker activation, stop the preview server and navigate to an uncached
   protected URL. The offline document should appear at that URL. Some automation
   offline emulation leaves worker fetches connected; stopping the local server
   verifies a real network failure.
6. Restart the server and retry. The server must check the session again and redirect
   an unauthenticated user to login.
7. Leave a tab open, change a public asset, rebuild, restart the server, and focus the
   tab. The update prompt must appear without clearing form fields or reloading.
   Test dismissal, deliberate acceptance, and multiple tabs.
8. Check desktop and mobile layouts, keyboard access, guidance, offline notices, and
   update error states for Georgian copy and accessible labels.

To regenerate matching icons on Windows, run
`powershell -File scripts/generate-pwa-icons.ps1`. This uses the operating system's
drawing library and installs no packages.
